# Upgrade Guides

## Ballista 56.0.0

**Note:** Ballista `56.0.0` has not been released yet. The information provided
in this section pertains to features and changes that have already been merged
to the main branch and are awaiting release in this version.

### Deprecations

#### The scheduler's embedded Flight proxy is deprecated

`--enable-embedded-flight-proxy` (and `SchedulerConfig::enable_embedded_flight_proxy`)
is deprecated and will be removed in 57.0.0. The proxy puts result traffic on the
scheduler's process, where it competes with query planning and task scheduling,
and it scales only with the scheduler.

Deployments where clients cannot reach the executors should instead run the new
`ballista-result-service` binary, a stateless Arrow Flight service that forwards
each result fetch to the executor holding the partition, and point the
scheduler's `--advertise-flight-endpoint` at it, or at a load balancer in front
of several replicas:

```bash
ballista-result-service --bind-port 50055
ballista-scheduler --advertise-flight-endpoint ballista-results.example.com:50055
```

Clients need no changes. The embedded proxy keeps working throughout 56.x, so
you can compare the two and roll back without downgrading Ballista; the
scheduler logs a warning at startup while it is enabled.

Also deprecated:

- `SchedulerConfig::with_enable_embedded_flight_proxy`
- passing `--advertise-flight-endpoint` with no value, which starts the
  embedded proxy

### Behavior changes

#### Undecodable fetch tickets are rejected as `InvalidArgument`

Executors, the embedded proxy, and the Result Service now share one
implementation of partition fetches. A `DoGet` ticket that does not decode as a
Ballista action is reported with the gRPC status `InvalidArgument` everywhere;
executors used to report it as `Internal`.
